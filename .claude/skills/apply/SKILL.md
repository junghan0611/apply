# apply — 채용 지원의 반사신경 면

Repo: `~/repos/gh/apply` — **공개** 저장소(`github.com/junghan0611/apply`).
증거 우선·사람이 최종 결정하는 채용 지원 워크스페이스이자 공개 사례 기록.

`AGENTS.md`(계약)·`NEXT.md`(지금 한 걸음)·`applications/LEDGER.md`(원장)가 *무엇/언제*를
담는다면, 이 스킬은 **매번 다시 당하는 것**을 담는다. 아래 항목은 전부 **실제로 일어난 사고**이고
날짜가 붙어 있다.

> ⚠ 이건 generic 구직 조언이 아니다. **이 저장소 오퍼레이터의 핸드북**이다.
> **공고는 예고 없이 닫히므로 속도가 값이다. 동시에 공개 저장소라 되돌릴 수 없는 실수가 더 비싸다.**

## 0. 시간이 첫 번째 제약이다 — 공고는 9일이면 닫힌다

**읽기의 값은 시간과 함께 감가한다.** 2026-09-09 에 담당업무 본문까지 읽고 「정면」으로 판정한
후보가 9일 뒤 둘 닫혔다:

| 잃은 것 | 무엇이었나 |
|---|---|
| **에스투더블유(S2W)** FDE (AI Platform) | 원티드 배치 「GLG 축과 정면」 1번 |
| **모레** AI Agent System Engineer | 리멤버 배치 1번. A2A·MCP·LangGraph 정면 |

- 🔴 **`due_time: null` 은 상시 채용이 아니다.** 닫힌 9건 대부분이 null 이었다. 마감일 없음 =
  **예고 없이 닫힌다**는 뜻이다.
- **후보를 읽었으면 그 세션 안에서 `new.sh` 까지 간다.** `INBOX-*.md` 에 남는 것은 후보이지
  지원이 아니다. 「다음에 GLG 가 고르면」으로 미루면 그 사이 닫힌다.
- 생존은 추측하지 말고 **재측정**한다:
  ```bash
  # 원티드 — 로그인 없이 job.status 를 직접 읽는다
  curl -s "https://www.wanted.co.kr/api/v4/jobs/<id>" | python3 -c \
    'import json,sys; j=json.load(sys.stdin)["job"]; print(j["status"], j.get("due_time"), j["position"])'
  ```
  `active` / `close` / `draft` 가 온다. `draft` 는 **원티드 면에서만 안 보이는 것**이라
  회사 보드가 정본이면 죽었다고 판정하지 않는다(구글·아마존이 그랬다).

## 1. 판정 — 제목으로 고르면 정확히 반대로 고른다 (2026-09-18 실측)

**판정 자리는 언제나 JD 의 담당업무 항목**이다. 회사 소개의 「AI 기반」도, 직무명의 「FDE」도
근거가 아니다. 2026-09-18 에 44건을 담당업무 원문 **인용**으로 재분류했더니 이렇게 뒤집혔다:

| 제목·요약으로 본 판정 | 담당업무를 읽은 판정 |
|---|---|
| 스켈터랩스 FDE ⭐⭐ 정면 | ⛔ 서비스 — 「고객사 요구사항 분석 및 맞춤형 AI 솔루션」 |
| 클리카 FDE Robotics (엣지 배포라 시스템일 것) | ⛔ 서비스 — 「AI SI, PoC, Pilot 수행」 |
| 위즈코어 「임베디드 개발자」 제목만 확인 | ✅ 시스템 — 실제 열린 req 는 온프레미스 K8s 플랫폼 |
| 마이클 「Data Engineering」 | ✅ 시스템 — 실제로는 Platform Engineering req |

- **요약하지 말고 인용한다.** 판정 근거를 `「…원문…」` 으로 옮긴다. 요약은 자기 프레이밍을
  근거로 세탁하는 자리다.
- **시스템 문장과 서비스 문장이 둘 다 있으면 둘 다 인용하고 애매로 둔다.** 억지로 한쪽에 넣지 않는다.
- 두 축은 **독립**이다 — `AGENTS.md` §시스템 축(무엇을 만드는 자리인가) + §둘째 축(요건·증거
  매트릭스). 시스템 축이어도 직접 증거 0 이면 hold 다.
- **매트릭스는 그 건 `submission.md` 에 적는다** — JD 필수요건 3개를 뽑아 각각
  `[직접 공개 증거 / 명시적 재직 사실 / 없음]`. 이게 **다음에 무엇을 먼저 낼지 정하는 값**이다.
  `reach`(직접 증거 1개)는 **전체에서 2~3건으로 제한**하고, 각각 「왜 이 간극을 감수하는가」를
  한 줄 적는다. 못 적으면 hold 다.
- 🔴 **컷이 부인하는 것을 JD 가 필수로 요구하면 내지 않는다.** 위즈코어가 그 자리였다 —
  `platform-engineer` 컷이 production K8s 운영을 명시적으로 부인하는데 JD 는 필수로 요구했다.
  정직한 문서 두 장이 서로 모순된 채로 나간다.

## 2. 새 후보를 올리기 전에 — 원장을 먼저 연다

```bash
grep -i "<회사명>" applications/LEDGER.md
```

2026-09-18 에 이 대조를 빼먹어서 **인핸스**(`rejected` 2026-08-04)가 후보로 다시 올라왔다.
같은 배치에서 모레(`rejected`)·스켈터랩스·마키나락스(둘 다 `submitted`)도 함께 올라왔다.

- **`rejected` 회사는 기본 제외.** 다른 직무라도 그렇다. GLG 판정 — 「떨어졌고 그대로 다시
  지원 안 한다」.
- **`submitted` 회사는 「새로 낸다」가 아니라 「이미 열린 경로」다.** 마키나락스는 **담당자
  추천으로 들어간 건**이라 새 req 를 따로 내는 것보다 그 담당자에게 묻는 쪽이 낫다.
- 후보 파일 행에 대조 결과를 붙인다. **「원장에 없음」도 값이다.**

## 3. Case ≠ packet ≠ ready — 섞으면 진척을 부풀려 보고하게 된다

| 단계 | 뜻 | 상태 |
|---|---|---|
| **case** | 폴더 · `JD.md` · `LEDGER.md` 행이 생겼다 | `draft` |
| **packet** | 붙일 컷 확정 + 폼 문항·필수 슬롯·글자수 캡 **실측** 완료 | `draft` |
| **ready** | 사람이 제출만 하면 되는 상태 | `ready` |

2026-09-18 에 22건을 만들고 **「22건 제출 패킷」이라 보고했는데 컷 미정·폼 미실측**이었다.
교차검수에서 잡혔다. **보고할 때 이 구분을 지킨다.**

### 🔴 `JD.md` 는 공고 전문을 복제하는 곳이 아니다

공개 계약은 **URL · 판정에 필요한 인용 · 요약**이다(`AGENTS.md` §공개는 현재 계약이다).
제3자 원문을 public repo 로 복제하지 않는다. 케이스를 만들 때 「원문 보존」이라는 말에 끌려
공고를 통째로 붙이지 마라 — **판정 근거가 된 문장만** 인용으로 남긴다.

### 제출한 **직후** 닫는다 — 사후 회수는 이 리포의 반복 실패다

한 건은 셋이 **동시에** 맞아야 닫힌다(`AGENTS.md` §기록 닫힘):

1. `LEDGER.md` 가 날짜와 함께 `submitted`
2. 그 건 `submission.md` 가 `submitted` 이고 **업로드 스냅샷을 지목**
3. 개인 필드는 사람이 완료했고 **값은 저장하지 않았다**고 적혀 있음

**사람의 보고 직후에 갱신한다.** 미루면 Gmail 을 뒤져 사후 회수하게 된다 — 2026-08-28 리멤버
14건, 2026-09-04 원티드·그리팅 5건, 2026-09-16 6건. **세 번 반복됐고 매번 잃는 것이 같다:
복원 불가능한 공고 원문과 URL.** 낼 때 남기는 것이 유일한 방어다.

**제출 완료 건의 `submit/` 스냅샷을 재빌드·덮어쓰지 않는다.** 그때 낸 그 문서가 계보다.
이력서를 다시 빌드했다고 과거 제출의 지문을 갱신하면 「무엇을 냈는가」가 사라진다.

## 4. 채널별 반사신경

### 원티드 — 공개 API, 브라우저 불필요

```bash
applications/wanted.py detail <id> <id> ...   # 담당업무·자격요건 본문
applications/wanted.py scan --tags <id>       # 목록 수집 (판정은 사람이)
applications/wanted.py tags                   # 직무 카테고리 id
```
- `tag_type_ids` 는 **한 요청에 5개까지**(6개부터 422). `scan` 이 알아서 쪼갠다.
- **검색어는 strict 필터가 아니다** — `query` 는 API 에 그대로 넘어가고 회사·태그·본문을 섞어
  느슨하게 매칭한다(`wanted.py:31-36,110-115`). 제목만 거르는 게 아니므로 **카테고리와 JD
  본문으로 다시 확인**한다.
- 지원경로(원티드 자체 ↔ 회사 ATS)·폼 문항은 **API 에 없다.** 추측으로 채우지 말고 「미실측」.

### 리멤버 — 로그인 전용. 두 번 사고 난 자리다

- 🔴 **「지원하기」·「간편 지원하기」·「입사지원」 을 어느 화면에서도 클릭하지 않는다.**
  과거에 「주요업무」 탭을 누르려다 오클릭해 **지원 확인 페이지까지 들어갔다.**
  목록은 **스크린샷으로만** 훑고, 열 때는 **공고 제목 텍스트**를 누른다. 카드 안 버튼 영역 금지.
  본문은 `get_page_text` 로 통째로 읽는다.
- 🔴 **URL·엔드포인트 패턴을 저장소에 적지 않는다.** `docs/HISTORY-REDACTION.md`
  §login-gated-automation 이 그 지도를 history 전체에서 지웠다. 2026-09-18 에 `new.sh` 인자로
  URL 을 넘겨 `submission.md` 에 박힌 사고가 났다(발견 즉시 정정, 커밋 전이라 회수됨).
  **회사·직무·리멤버 id·판정·인용만 남긴다.**
- **URL 을 추측하지 않는다.** 저장소에 없는 것이 정상이다. 로그인된 목록 UI 를 걸어간다.
- 검색이 회사명 토큰을 그대로 안 태운다 — 「인핸스」는 「인헨스」로 쳐야 걸리고,

## 5. 문서 파이프라인 — 사실 한 벌에서 타깃마다 **생성**한다

같은 문장을 여섯 군데 깔아 둔 이력서 폴더는 흔하다. 이 리포는 반대로 간다 — **사실은 한 벌이고
타깃은 렌더된다.** 파이프라인 자체가 이 리포의 기술적 주장이므로 여기를 무너뜨리면 주장이 사라진다.

```text
resume/body.org                 사실 SSOT — 경력·프로젝트가 한 벌만
resume/targets/<cut>.org        프로필 매니페스트 — 모듈 선택·순서 + 직무 언어 절
resume/pipeline/latex-export.el CV_*_MODULES 해석 (export 전 hook)
resume/run.sh                   org → tex → pdf, 그리고 PDF 텍스트 실측 검사
resume/build/*.pdf              산출물 — 손으로 고치지 않는다
```

**생성이 주는 것 셋** — 이게 값이다:

1. **사실 한 번 고치면 7종 산출물에 전부 반영**된다. 컷마다 찾아다니지 않는다.
2. **매니페스트가 명시적이다** — 어느 경력 모듈을 어떤 순서로 실었는지 `CV_*_MODULES` 한 줄에
   드러난다. 컷 사이 차이가 diff 로 읽힌다.
3. **빌드가 PDF 텍스트를 다시 검사한다**(`run.sh:117-189`) — A4·활자 누락·`noexport` 누출·
   연락처·URL 5종·공개 증거 링크 2개 이상. 2026-08-01 에 `ax.junghanacs.com` 이 여섯 컷
   **전부에서 빠진** 사고가 이 게이트를 낳았다.

### 🔴 기계가 보장하는 것과 규율로 지키는 것을 구분한다

이 구분이 이 절의 핵심이다. **보장하지 않는 것을 보장한다고 쓰면 그 순간 이 리포가 진다.**

| | |
|---|---|
| **코드가 보장** | 모듈 선택·배열은 include 가 풀린 **임시 export 버퍼**에서만 일어난다 (`latex-export.el:97-140`). **소스 파일은 빌드로 바뀌지 않는다** — `platform-engineer` 빌드 전후 `body.org`·타깃의 SHA-256 동일 확인(terra 실측, 2026-09-18) |
| **빌드가 강제** | 타깃마다 `#+CV_GOQUAL_MODULES:` 존재 · `* Public Evidence` 절 존재 · `github.com/junghan0611/` 링크 **2개 이상** (`run.sh:72-83`) |
| **규율로만 지킴** | ⚠ **텍스트 중복을 코드가 막지 않는다.** `body.org` 문장을 타깃 Summary 로 복사해도 `validate_target_source()` 는 통과한다 — 동등성 검사가 없다 |
| 〃 | ⚠ `CV_INDEPENDENT_MODULES` 는 **필수가 아니다.** 빼면 hook 이 `(when requested …)` 에서 아무것도 안 하고 independent 모듈이 **전부 그대로** 나간다 |
| 〃 | ⚠ 같은 모듈 id 를 두 번 적으면 **두 번 들어간다.** dedupe 없다 |
| 〃 | ⚠ `run.sh verify` 는 PDF 가 소스에서 나왔음을 **증명하지 않는다.** 이미 있는 PDF 의 텍스트·형식만 본다. 수기 수정 금지는 **규율**이지 게이트가 아니다 |

그러니 **하지 말 것**: `body.org` 문장을 타깃으로 복사(강조하고 싶어서·순서 때문에·이 컷에서만
다르게 쓰고 싶어서 — 전부 같은 실패. 순서는 `CV_*_MODULES` 로, 강조는 Summary 로) ·
타깃 Summary 에 **새 경력 사실 쓰기**(타깃은 뷰다) · PDF 수기 수정 ·
`body.org` 에 그 축의 사실이 없는데 컷부터 만들기(§6 실측 표를 먼저 본다).

```bash
cd resume
./run.sh check                    # 도구·폰트 preflight (emacs·xelatex·Pretendard)
./run.sh target platform-engineer # 한 컷만
./run.sh all                      # 전체 빌드 + verify 까지 한 번에 (run.sh:205-210)
```

`targets/*.org` 는 **글롭**이라 파일만 만들면 등록된다. 계약 전문은 `resume/AGENTS.md`.

**공개 게이트의 오탐과 정책 허용과 진짜를 구분한다.** 2026-09-18 에 넷이 실패했는데 성격이 둘이었다:

| 실패 | 성격 |
|---|---|

둘을 「무해」로 뭉치지 않는다. 뭉치면 안전 게이트를 가볍게 보게 된다.

  느슨하게 하면 진짜가 와도 못 알아본다.
- **무해화 규칙에는 반드시 「너무 많이 지우지 않는지」 self-test 를 같이 넣는다.**
  지우는 쪽만 검사하면 규칙이 조용히 넓어져도 초록불이 된다.
- 🔴 **`IDENT_ALLOW` 에 주소를 더하는 것은 그 주소를 공개 신원으로 선언하는 일이다.**
  에이전트가 조용히 늘리지 않는다 — GLG 결정이다.
- 게이트는 **값을 찍지 않는다**(경로·범주만). 그 계약을 우회해서 세션 로그로 흘리지 마라.
