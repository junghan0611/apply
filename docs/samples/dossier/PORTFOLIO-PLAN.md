# NHN 포트폴리오 — 편집·이미지 계약 (v3, 2026-07-20)

> v2에서 바뀐 것: 소재를 공개 베이스 3종 기준으로 회수했고, timeline 증거를 접합했으며,
> 이미지를 GLGMAN 세계관으로 전환했다. 페이지 예산은 없앴다. 아래 「v2 교차검토 결정」 절은
> **역사 기록**이며 현재 계약이 아니다.

## 목적

`competency.org`가 “아직 이름이 굳지 않은 역할을 먼저 살아 온 하나의 흐름”을 선언한다면,
`portfolio.org`는 그 흐름을 **프로젝트별 문제·경계·판단·운영·인계로 증명**한다.

철학을 반복하지 않는다. 프로젝트 이름을 나열하지 않는다. 각 프로젝트에서 무엇이
달라졌고, 왜 그렇게 설계했으며, 누가 어떻게 이어받는지를 보여준다.

## 프로젝트 순서

1. **AX 전환 인프라·도메인 에이전트** — 1단계 기반 구축(GPU·임베딩·파이프라인) + 2단계 도메인 에이전트
2. **OpenClaw 플랫폼 운영** — 변경·인시던트·롤백·승격 규칙
3. **andenken** — 런타임 밖으로 분리한 에이전트 기억·검색 계층
4. **entwurf + forge-config** — 하네스 디스패치와 검토 가능한 공유 작업면
5. **Embedded Linux·Backend·제품** — AX 계층 아래의 현실 시스템

## 프로젝트 공통 문법

각 프로젝트는 같은 순서로 쓴다.

1. **한 줄 명제** — 이 프로젝트가 증명하는 것
2. **맥락과 문제** — 왜 기존 방식으로는 부족했는가
3. **소유 범위와 협업면** — 내가 맡은 판단·구현·운영, 다른 조직과 맞닿은 경계
4. **시스템 경계** — 생성형 인포그래픽 한 장
5. **핵심 판단** — 기능 목록이 아니라 선택과 포기. 개수 제한은 두지 않는다(P2는 timeline 회수 뒤 3개가 됐다)
6. **운영 후 상태 변화** — 허영 수치가 아니라 실제로 달라진 일
7. **인계·문서** — 다음 사람과 에이전트가 어디서 이어받는가
8. **확인 지점** — 공개 저장소·PR·노트 또는 `[사내]` 경계

`JD 관련성` 문단은 반복하지 않는다. 본문 자체가 JD를 증명하고, 대응표는 `:noexport:`
점검면으로만 둔다.

## 수치 원칙 (v4 — 2026-07-29 GLG. 내가 만든 숫자 ✗ / 남이 만든 기록 ✓)

**v3 를 한 칸 더 민다.** v3 는 성능 수치만 뺐는데, GLG 판단은 **자가 측정 수치는 작업량도
마찬가지로 도움이 안 된다**는 것이다. 기준은 「크냐 작냐」가 아니라 **「내가 만든 숫자냐,
남이 남긴 기록이냐」**다.

- **성능 수치는 넣지 않는다.** 부팅 45.4→5.8초, 메모리 816→246MiB 류. 벤치마크 자랑이고
  외부에서 검증도 안 된다. OpenClaw 절에서 이미 전부 뺐다.
- ⛔ **자가 측정 작업량 수치도 넣지 않는다 (v4 신설).** 테스트 163개, 코드공유 96%,
  임베딩 2,945건, 하루 24커밋 류. 스스로 세어 스스로 적은 숫자라 검증 축이 없고,
  규모로 읽히는 자리에서는 오히려 작아 보인다. **2026-07-29 이력서에서 전부 걷어냈다.**
- ✅ **라이브 주소에서 확인되는 누적 기록은 넣는다.** Working Corpus(노트·서지·커밋·연속
  저널일·가든 페이지·건강 기록일·스킬 수) + `agenda.junghanacs.com` + 측정일.
  **대체 불가능한 기록**이고 읽는 쪽이 클릭해서 확인한다.
- ✅ **제3자가 남긴 숫자는 넣는다.** 기여받은 PR 의 파일·줄 수, npm 설치 수.
  내가 만든 게 아니라 **남의 행동이 남긴 기록**이라 성격이 다르다.
- **사건의 시간축은 넣는다.** 날짜·시각·커밋 SHA. timeline으로 회수했고 공개 커밋은
  클릭 가능한 링크로 단다. **숫자를 뺀 자리는 이것으로 대신한다.**
- 규모를 크게 보이게 할 뿐 판단을 설명하지 못하는 숫자는 계속 내린다.
- 공개 이력서와 정합하는 수치를 최댓값으로 갈아끼우지 않는다(cherry-picking으로 읽힌다).

## 프로젝트별 단일 명제와 그림 계약

### 1. AX 전환 인프라·도메인 에이전트

- **명제:** AI가 돌아갈 기반을 먼저 깔고, 그 위에 도메인의 주인에게 붙는 에이전트를 세웠다.
- **1단계(2025-06~09):** GPU 클러스터·NixOS·10G, n8n+pgvector, Airbyte 파이프라인,
  Zero Trust 포털, 임베딩·리랭킹 **직접 서빙**. JD 주요업무① 정중앙이므로 «보조»로 내리지 않는다.
- **2단계(2026-05~):** `voscli`(첫날 데이터 계약 확정), `incidentcli`, 비서실장 에이전트,
  Forge 커넥터, PSIRT. 개인정보·자격증명 경계와 운영팀 피드백 루프.
- **그림:** 손대지 않은 원천 저수조 → 좁은 수문(읽기 전용) → 끊긴 붉은 변경 경로 →
  담당자에게 닿는 실 하나가 원천까지 되짚어진다. 자격증명은 케이블 없는 별도 금고.

### 2. OpenClaw 플랫폼 운영

- **명제:** 에이전트 도구를 사용한 것이 아니라 상류 변경과 장애를 운영 규칙으로 번역했다.
- **본문 중심:** 증상 계측, 클린 부팅 재현, 마지막 정상판 롤백, 업스트림 수정 식별,
  승격 규칙.
- **그림:** 변경 → 회귀 → 재현 → 롤백 → 수정 식별 → 승격 규칙의 판단 시간축.
  수치는 판단에 필요한 작은 증거 태그로만 쓴다.

### 3. andenken

- **명제:** 기억을 특정 런타임에서 떼어 여러 하네스가 소비하는 독립 계층으로 만들었다.
- **본문 중심:** 세션·가든 두 라이브 트랙, 벡터+FTS, 점수 정규화, 한↔영 질의,
  회수 추적.
- **그림:** 세션/가든 → 임베딩·FTS → LanceDB → 점수 정규화 → 통합 검색 표면.
  active recall과 dream은 구현과 같은 무게로 그리지 않고 경계·로드맵으로만 표시한다.

### 4. entwurf + forge-config

- **명제:** 서로 다른 하네스가 세션 기억이 아니라 검토 가능한 durable state를 기준으로
  협력하게 했다.
- **본문 중심:** 정체성 기반 디스패치, 하네스 비종속, Forgejo 이슈·리뷰·인계,
  사람이 구현 우선순위를 소유하는 non-goal, 외부 Cortex 기여.
- **그림:** 서로 다른 세 기계장치의 문(소켓·우편함·직접 주입)에 여우가 하나씩 서 있고,
  **네 번째 여우는 문 없이 담 밖에서** 소포만 넘긴다(Codex = 아직 시민 아님).
  중앙 원장에 닿은 빛만 남고 나머지는 흩어진다.
- **⚠ 사실 경계:** ACP 백엔드는 현재 Claude 하나다. «ACP로 모두 연결»로 쓰지 않는다.

### 5. Embedded Linux·Backend·제품

- **명제:** 급히 넘겨받은 시스템을 이해 가능한 계약으로 바꾸어 양산까지 보냈다. 인계로 열려 인계로 닫힌다.
- **본문 중심:** 자원 제약 Linux 장치, Zig 펌웨어, Go 서버, Flutter 앱, 연결형/폐쇄망,
  실제 제품 출시.
- **그림:** 장치 → 서버 → 앱 → 클라우드/로컬 백엔드의 제품 세로축과 프로토콜 경계.
  Temporal·Saga 제안은 필요하면 상세 MD로 내린다.
