공고의 우대 첫 줄을 읽고 지원합니다. CLI 기반 AI 도구를 자체 skill·hook·agent·MCP server 로 customize 하고, openclaw 같은 personal AI agent 를 직접 쓰고 만든다 — 제가 매일 하는 일을 그대로 옮긴 문장이었습니다.

지금 회사에서 열두 명 규모 개발 조직의 에이전트 축을 혼자 세웠습니다. 스마트홈 허브 펌웨어를 양산까지 올리는 일을 하면서, 동시에 팀이 AI 와 일하는 방식을 만들었습니다. 스킬 정본 하나를 여섯 개 하네스로 팬아웃시키는 구조를 짰고 — Claude Code, Codex, pi, Antigravity, OpenClaw 가 각자의 인증과 정체성을 유지한 채 같은 역량을 공유합니다 — 셀프호스팅 Forgejo 를 작업 원장으로 세워 이슈 생성, 라벨, 1차 리뷰, 핸드백까지 에이전트가 함께 굴리게 했습니다. 사내 도구를 만들어 동료에게 임팩트를 준다는 것이 무엇인지, 만든 쪽에서 알고 있습니다.

Central Data Layer 는 제가 개인 규모에서 이미 풀어 본 문제입니다. 노트와 세션, 서지와 시간축을 하나의 ID 축으로 묶어 정형과 비정형을 한 자리에서 다루게 했고, 그 위에 벡터 검색과 전문 검색을 점수 정규화로 합친 하이브리드 검색을 올려 매일 운영합니다. MCP 와 ACP, A2A 는 써 본 쪽이 아니라 만든 쪽입니다. 하네스끼리 서로를 id 로 호출하는 디스패치 기반을 오픈소스로 두고 상용 클라우드 ARM 위에서 스무 번 넘는 업스트림 버전 사이클을 통과시켰습니다.

담당 업무 다섯 번째, 사내 AI 사용 정책과 스킬 가이드를 쓰고 교육 세션을 운영하는 일은 저에게 부산물이 아닙니다. 저는 에이전트가 무엇을 소유하고 무엇을 소유하지 않는지를 운영 헌장으로 못 박는 방식으로 일해 왔고, 그 판단 과정을 날짜와 함께 공개 저장소와 디지털 가든에 남겨 왔습니다. 만드는 사람과 전파하는 사람이 갈라져 있으면 Flywheel 이 한 바퀴에서 멈춘다고 생각합니다. 쓰는 사람이 곧 만든 사람일 때만 사용이 데이터가 되고 데이터가 다시 도구를 고칩니다.

경계는 먼저 밝히겠습니다. Kubernetes 운영 경험이 없습니다. Snowflake·Databricks 같은 관리형 Lakehouse, dbt·Airflow 같은 오케스트레이션 도구는 실무로 다뤄본 적이 없습니다. 다만 데이터 파이프라인 자체를 안 다뤄본 것은 아닙니다. 셀프호스팅 Airbyte로 MongoDB와 Google Sheets 같은 이종 소스를 PostgreSQL JSONB 한 곳으로 모으는 파이프라인을 직접 설치·운영하고, 운영팀이 n8n에 새 자동화를 추가할 때 그 검수도 제가 맡습니다. 최근에는 전략기획실의 엑셀 경제지표를 원본 손실 없이 JSONB로 보존한 뒤 AI가 읽기 쉬운 JSONL 단위로 재표현하는 데이터레이크 구조를 직접 설계했습니다. 목표는 예측 모델이 아니라 현재 시점의 최선 판단 재료를 드러내는 것이었습니다. OLAP DB 실무는 얇고, PostgreSQL 과 pgvector 축입니다. Salesforce 나 SAP 같은 엔터프라이즈 SaaS 통합 경험도, 의료 도메인 경험도 없습니다. 백엔드라는 직함으로 3년을 채운 이력도 아닙니다. 펌웨어에서 서버와 앱으로, 다시 에이전트 인프라로 경계를 넘어온 이력입니다. 다만 그 넘나듦이 이 팀이 하는 일과 같은 모양이라고 생각합니다. 정답이 정해지지 않은 문제를 앞에 두고 무엇을 만들어야 조직이 한 단계 올라가는지 찾는 일이니까요.
