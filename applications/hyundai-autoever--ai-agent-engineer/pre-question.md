# 사전질문 답변 — 폼에 붙여넣을 원문

> 폼 질문: *(선택) 이력서 내용 외에 추가적으로 설명하거나 어필하고자 하는 내용이 있으시면
> 자유롭게 작성 부탁드립니다. (최대 1,000자)*

이 자리는 **이력서가 못 하는 일**을 해야 한다. 이력서는 무엇을 했는지 나열하고, 자기소개서는
사람을 보여준다. 사전질문은 **「담당 업무 네 줄에 내가 정확히 어떻게 맞는가」를 채용담당자가
30초 안에 판정하게 만드는 자리**다. 그래서 서사를 쓰지 않고 네 줄에 1:1로 붙인다.

첫 줄은 이력서가 영문이라는 사실을 먼저 처리한다 — 읽는 사람이 PDF를 열고 당황하는 것보다
낫다. 마지막 줄은 증거 확인 경로다. 이 공고는 「지원서가 사실과 다르거나 증빙이 불가할 경우」를
명시했으므로, 검증 경로를 스스로 여는 편이 맞다.

## 붙여넣을 본문 (줄바꿈 포함 966자 · 줄바꿈 제외 953자)

```text
이력서는 영문 한 벌로 관리해 그대로 첨부했습니다. 국문 자기소개서를 함께 올렸으니 그쪽을 먼저 보셔도 됩니다.

담당 업무 네 줄이 제가 이미 하고 있는 일과 겹쳐 지원했습니다.

Orchestration — 서로 다른 에이전트 하네스가 서로를 id로 부르는 디스패치 기층(entwurf)을 만들어 npm에 공개했습니다. 상위 에이전트가 대신 지휘하는 구조가 아니라 사람이 오케스트레이터로 남는 구조이고, 만난 적 없는 개발자가 기업용 런타임 백엔드를 붙이는 기여 PR을 열었습니다.

MCP 채널 연동 — 하네스마다 다른 접속면(컨트롤 소켓, 우편함, 네이티브 주입, 외부 MCP 송신자)을 각자의 인증·대화록 경계를 지킨 채 연결했습니다. 하나로 통일하지 않은 것이 설계입니다.

API·성능 — 에이전트 런타임을 5개월간 상시 운영하며 20회 이상 상류 버전을 올렸고, 지연 회귀를 계측해 근거를 들고 롤백한 뒤 부팅 45.4초를 5.8초로, 메모리 816MiB를 246MiB로 줄였습니다. 회사에서는 임베딩·리랭킹 모델을 외부 API로 넘기지 않고 사내 GPU에서 직접 서빙했습니다.

업무 자동화 — 사내에서 받은 요청은 「대시보드를 만들어 주세요」가 아니라 「제가 없어도 돌아가게 해 주세요」였습니다. 그래서 대시보드 대신, 이미 돌아가는 운영·상담 시스템 위에 담당자가 쓰는 읽기 전용 접점을 붙였습니다. 증거 계약을 통과하지 못하면 경고를 남기고 지나가는 대신 멈추게 했습니다. 첫 사용자가 사람이 아니라 담당자 에이전트이기 때문입니다.

경계도 밝힙니다. 주력 언어는 Go·Clojure·Zig·TypeScript이고 Python은 파이프라인·도구 수준입니다. 모델 학습·파인튜닝은 제 축이 아니며, A2A 규격 구현 경험도 없습니다. 제 축은 에이전트를 조직 안에서 실제로 돌아가게 만드는 쪽입니다.

증거는 공개돼 있습니다. github.com/junghan0611 · notes.junghanacs.com
```

- 여유가 얇으므로 붙여넣은 뒤 **폼의 카운터(`0/1000`)를 반드시 눈으로 확인한다.**
- 넘치면 「업무 자동화」 문단의 마지막 두 문장부터 지운다 — 요청의 대비(대시보드 → 없어도
  돌아가게)가 이 문단의 핵심이고, 뒤의 부연은 자기소개서 §3-④에 같은 내용이 있다.

## 쓰지 않은 것 (의도)

- **연봉·입사 가능일**을 여기에 쓰지 않았다. 폼이 묻지 않았고, `FAQ.md` §4가 아직
  `⚠ GLG 확정 필요`다. 묻지 않은 조건을 먼저 꺼내면 협상 자리를 잃는다.
- **박사 수료**를 학위처럼 쓰지 않았다. 우대사항이 「석/박사 학위 보유」인데 수료는 학위가
  아니다. 자기소개서 머리말에 「석사 (박사 과정 수료)」로 정확히 적었다.
- **가든 노트 수·저널 연속일수**를 넣지 않았다. 이 공고의 담당 업무 네 줄과 직접 겹치지 않아
  1,000자를 쓸 자리가 아니다. 자기소개서와 이력서에는 있다.
- **회사 내부 고유명사**(제품명·고객사·사내 시스템 이름)를 넣지 않았다. 「회사에서는」으로만
  가리켰다.
