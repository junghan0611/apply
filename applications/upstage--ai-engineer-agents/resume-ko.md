# 요약

저는 모델을 둘러싼 시스템을 만들고 운영합니다. 하네스의 경계, 검색, 권한, 증거 계약,
업그레이드 정책, 그리고 사람이 책임을 지는 작업면이 그 대상입니다. 반복되는 상류 변경을
거치며 자체 호스팅 멀티에이전트 하네스를 운영했고, 시맨틱 메모리를 독립 하이브리드 검색
계층으로 분리했으며, 각 하네스의 대화기록·인증·런타임 소유권을 보존하는 디스패치 기층을
공개했습니다.

제 전문성은 파운데이션 모델 학습이나 파인튜닝이 아닙니다. 모델 호출이 끝난 뒤에도 작동해야
하는 계층을 다루는 응용 AI 시스템 엔지니어링입니다. Go·Clojure 서비스, PostgreSQL/pgvector,
NixOS·컨테이너, 임베디드 Linux, 프로토콜과 실제 도메인 데이터를 바탕으로, 에이전트가 어디까지
행동할 수 있는지, 무엇을 남겨야 하는지, 어디서 멈춰야 하는지, 다른 사람이나 에이전트가 어떻게
경로를 재현할 수 있는지를 설계합니다.

# 핵심 역량

- **에이전트 플랫폼 운영** — 상류 버전 추적, 단계적 승격, 회귀 계측, 롤백 정책, SLO, 복구 가능한 세션 연속성
- **하네스와 에이전트 시스템** — 디스패치, 정체성·인증 경계, 위임 계약, 도메인 담당 에이전트, 사람 PM 중심의 검토 루프
- **지식공학 / RAG** — 임베딩·하이브리드 검색, 사내 서빙 리랭킹·임베딩, 한영 교차언어 확장, 리콜 추적, Org/Denote 지식 그래프
- **백엔드와 인프라** — Go·Clojure 서비스, PostgreSQL/pgvector, Docker, 선언형 NixOS, GPU 인프라, 재현 가능한 빌드·문서 파이프라인
- **임베디드와 엣지 AI** — ARM/RISC-V Linux의 온디바이스 sLLM·NPU 배포. 시스템 기반 계층을 직접 다뤄 온 경험으로 에이전트 루프를 설계

# 경력

## GoQual Inc. — 풀스택 아키텍트 (2025.06–현재)

### 도메인 담당 에이전트와 에이전트 작업면 (2026.05–현재)

다른 팀에서 반복해서 받는 요청은 “대시보드를 만들어 달라”가 아니라 “내게 의존하지 않고 이 일이 돌아가게 해 달라”입니다. 대시보드가 부담만 옮기는 경우, 저는 도메인 소유자에게 붙는 에이전트를 세웁니다.

- **VOC 워크벤치** — 일일 고객지원 데이터를 대상으로 한 정량 귀추 도구입니다. 모든 수치의 단위·기간·포함 정책을 고정하고, 각 수치를 하나의 대화 ID까지 추적하게 하며, 기준선과 다른 신호를 드러냅니다. 회사 데이터는 공개하지 않은 채, 공개 `abductcli` 방법론의 운영 대응물로 만들었습니다.
- **인시던트 워크벤치** — 덤프를 저장하지 않고 실제 소스에서 직접 읽는 읽기 전용 증거 도구입니다. 플랫폼 DDL 카탈로그·디바이스 로그·런타임 미러를 단일 KST 시간축에 맞추고, 증거 계약이 깨지면 경고만 내지 않고 멈춥니다.
- **Forge 커넥터** — 대화를 자체 호스팅 Forgejo의 검토 가능한 작업 항목으로 바꾸는 에이전트입니다. 이슈·라벨·1차 검토·되돌려주기를 담당하며, 봇은 구현자가 아니라 디스패처·기록자입니다. 공개 대응물은 `forge-config`입니다.
- **비서실 에이전트** — 트랙·소유자·결정·원장을 지닌 작업면입니다. 외부 제보 취약점에 대해서는 제품 보안 대응(PSIRT) 접수, 재현, 영향 평가, 벤더 에스컬레이션, 규제기관·고객 응답을 다룹니다.

### 스마트홈 허브 — 펌웨어에서 제품까지 (2025.12–현재)

- **SKS Hub** — Zig 기반 Zigbee/Wi-Fi 게이트웨이 펌웨어를 양산에 적용했습니다. 레거시 C Zigbee SDK 통합을 Zig의 타입 안전 FFI 계층 뒤로 다시 작성하고, 드라이버·프로토콜·클라우드 계층을 가로르는 결정적 상태 머신(단일 `HubState`, 순수 `transition()`)을 만들었습니다. AI 에이전트를 페어 프로그래머로 둔 24시간 에이징 테스트 자동화도 구축했습니다.
- **원래 계약 밖의 제품화** — 펌웨어 납품물을 완결된 제품으로 만들기 위해 서버(Go)와 컴패니언 앱(Flutter)을 직접 만들었습니다. 하나의 프로토콜이 두 개의 교체 가능한 백엔드(연결형 배포의 AWS IoT, 폐쇄망의 로컬 mTLS 브로커)를 서비스하며, 양쪽에서 펌웨어 수정 없이 동작하게 했습니다. 실물 하드웨어에서 멀티 허브 팬아웃을 검증하고 단조 버전 기반 섀도 미러링을 구현했습니다.
- **차세대 허브** — 포팅 대상을 벤더 sysroot 기반 ARMv7/glibc에서 정적 링크 musl의 RISC-V(SG2000)로 옮겼습니다. 보드 HAL을 추출해 허브 코어가 실행 보드를 알 필요 없게 했고, Zigbee 전송은 Zigbee2MQTT(EFR32MG24)에 맡겼습니다. 하드코딩된 7개 디바이스 유형 핸들러를 걷어 기기 비종속 구조로 전환했습니다.

### 온디바이스 AI 스마트홈 허브 (2025.09–현재)

- **HomeAgent** — 온디바이스 AI 에이전트를 갖춘 오픈소스 Matter 허브입니다. 하나의 Go 코드베이스가 RPi5 + Hailo-8 NPU(Yocto)와 RK3576(Android)에서 동작하고, Flutter가 셸을 맡습니다. matterjs 브리지를 통한 Matter/Thread용 BLE 커미셔닝과 OTBR 통합을 구현했습니다. 사람을 PM으로 둔 세 에이전트의 병렬 작업은 세션 간 파일 충돌 없이 유지됐습니다.
- **Matter 월패드 (고객 프로젝트)** — RK3576 + Android 15, Thread RCP로서 ESP32-H2, `ot-daemon`을 갖춘 AOSP 네이티브 CHIP C++ SDK를 고객 자체 네임스페이스의 버전 관리 Android SDK(AAR)로 납품했습니다.
- **국가 R&D (IITP, 2025–2028)** — AI SoC 벤더와 함께하는 지능형 홈 프로그램입니다. sLLM 기반 음성 제어, Matter 통합, 가속기 계열을 가로지르는 NPU 워크로드 포팅을 담당하며 현재 2년 차입니다.

### 에이전트 플랫폼 운영 (2026.02–현재)

Oracle Cloud ARM에서 반복되는 상류 릴리스 변경을 거치며 자체 호스팅 멀티에이전트 하네스를 운영했습니다. 회전 중인 게이트웨이 프로세스로 인한 지연 회귀를 계측했고, 최신성 대신 증거로 롤백 대상을 선택했으며, 이후 정책을 남겼습니다. 두 버전을 한 번에 뛰어넘지 않고, 승격 전 비프로덕션 에이전트에서 최소 24시간 단계 운영하며, 응답성을 SLO로 둡니다. 이후 상류 릴리스가 근본 원인을 고쳤고, 정책은 언제 그 버전을 받아들일지 판단하는 기준이 됐습니다. 인시던트, 롤백 대상, 이후 정책은 공개 커밋 이력에 날짜와 함께 남아 있습니다.

### entwurf — 가든 시민 디스패치 기층

Claude Code·Codex·Antigravity·pi 같은 에이전트 하네스가 서로의 대화기록·인증·런타임을 소유하지 않고 ID로 서로를 주소화합니다. OAuth 프록시, CLI 대화기록 스크래핑, 백엔드 정체성 대체 없이 동작하며 npm에 공개했습니다.

### andenken — 독립 계층으로서의 시맨틱 메모리

벡터+FTS 하이브리드 검색과 점수 정규화를 사용하는 LanceDB, 개인 어휘 그래프를 통한 한영 교차언어 확장, 통합을 위한 리콜 추적을 구현했습니다.

### agent-config — 재현 가능한 스킬 작업면

노트·어젠다·서지·건강 데이터·Git 이력 위에 40개 이상 에이전트 스킬을 둔 PKM 기반 스택입니다. 세 층 한영 교차언어 검색 설계를 갖고, 빌드 CLI 산출물은 소스 개정·소스 트리 다이제스트·설치 바이너리 SHA-256 계보를 지닙니다.

### forge-config — 지속 가능한 에이전트 작업 원장

대화를 검토 가능한 Forgejo 이슈로 바꾸는 공개 운영 정책과 CLI 작업면입니다. 포착, 명시적 소유, 읽기 전용 1차 검토, 되돌려주기, 사람 거버넌스 구현을 다룹니다. 봇은 조용히 구현하지 않고 디스패치하고 기록합니다.

### memex-kb — 한국어 문서 도구사슬

`hwpx2org`, 스캔 문서 비전 전사, `epub2org`, 사무 형식으로 돌아가는 `org2odtdoc`, `textlint-ko`로 한국어 콘텐츠를 기계가 읽을 수 있게 합니다. 모든 것이 통과하는 메타문서로 Org-mode를 두며, 이는 데모 형식 변환이 아니라 한국 조직에서 반복되는 경계 문제입니다.

### 디지털 가든과 공유 시간축

2,200개 이상 공개 페이지, 3,500개 이상 Org-mode 노트, 1,600일 이상 연속 저널링으로 이뤄진 작업 코퍼스입니다. 사람과 에이전트는 emacsclient 소켓 위 경로 보호 Elisp API 10개를 통해 같은 org-agenda를 읽습니다. 로컬 Emacs·클라우드 봇·공개 웹이라는 세 소비자를 하나의 인터페이스로 잇습니다. 또한 IndieWeb POSSE 패턴을 뒤집은 ROSSE를 설계했습니다. 다듬기 어려운 바깥에서 날것의 글이 먼저 쓰이고, 가든에서 회수·수렴한 뒤 다시 배포됩니다.

### 에이전트가 질의할 수 있는 코퍼스 도구

실제 코퍼스를 위해 `denotecli`, `dictcli`, `gitcli`, `lifetract`, `bibcli`, `abductcli`를 만들었습니다. 모든 도구가 Denote ID를 쓰므로 커밋·저널·봇 로그·건강 기록일이 하나의 타임스탬프 체계에서 교차 참조됩니다.

# 제3자 검증

제 계정에 의존하지 않는 증거, 즉 다른 사람이 취한 행동입니다.

- **다른 사람이 entwurf 위에 만들었습니다.** 만난 적 없는 개발자가 Snowflake Cortex Code ACP 백엔드를 기여했습니다([entwurf#40](https://github.com/junghan0611/entwurf/pull/40), 11개 파일·+885줄). 제가 작성해 본 적 없는 엔터프라이즈 에이전트 런타임을 대상으로, 아키텍처가 주장한 바로 그 확장 경계를 찾아 사용했습니다. 자기서술 아키텍처 주장보다 강한 검증입니다.
- **다른 사람이 제 코드를 머지했습니다.** libghostty-vt 기반 Emacs 터미널 에뮬레이터 [dakra/ghostel](https://github.com/dakra/ghostel)에 두 패치가 받아들여졌습니다. [#343](https://github.com/dakra/ghostel/pull/343)은 IME 확정 텍스트를 전달하고 조합 중 리드로우를 막으며(+435줄), [#510](https://github.com/dakra/ghostel/pull/510)은 Lisp IME가 읽기 전용 버퍼 안에서도 조합할 수 있게 합니다. 모두 제가 소유하지 않은 코드베이스에서 한국어·CJK 입력을 고친 일로, `memex-kb`가 다른 방향에서 푸는 문제와 같습니다.
- **사람들이 설치합니다.** `@junghanacs/entwurf`는 2026년 7월 이전 30일 동안 npm 설치 1,395회를 기록했습니다.
