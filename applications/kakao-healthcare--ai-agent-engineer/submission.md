## 왜 이 회사의 이 직무인가

**지금까지 연 30여 건 중 공고 본문이 GLG 의 작업 자체를 가장 정확히 서술한 자리다.**
한화비전 건에 같은 문장을 썼는데, 이 공고는 한 단계 더 간다. 한화비전은 *만들라*고 했고,
이 공고는 **무엇을 만드는 일인지 GLG 와 같은 언어로 정의**한다.

> *"orchestration, memory, 도구 연동, 평가·관측, 안전 게이트를 갖춘 실행 기반 agent harness 를
> **기성 프레임워크의 조립이 아니라 밑바닥부터** 직접 설계하고 구현합니다."*

**「기성 프레임워크의 조립이 아니라」가 이 건의 전부다.** LangChain·LlamaIndex 를 쓴 이력이
없다는 것이 여기서는 감점이 아니라 **정확히 요구된 조건**이다. GLG 가 4년간 만든 것이
프레임워크 사용기가 아니라 그 아래 층이기 때문이다 — 하네스가 서로를 부르는 기층(`entwurf`),
기억을 하네스에서 떼어낸 독립 계층(`andenken`), 스킬 정본 하나가 여러 하네스로 퍼지는
표면(`agent-config`), 그리고 그 위에서 사람이 책임을 지는 작업 원장(`forge-config`).

**두 번째 담당 업무가 결정적이다** — *"하네스 위에 EHR 개발자가 **subagent, skill, workflow**
를 손쉽게 올릴 수 있는 인터페이스 설계·개발"*. 이것은 `agent-config` 가 이미 하고 있는 일의
문장 그대로다. 스킬 정본 한 벌이 **다섯 하네스**(Claude Code · Codex · pi · Antigravity ·
OpenClaw)로 팬아웃되고, 각 하네스는 자기 인증과 정체성을 유지한다. **「EHR 개발자」 자리에
「다른 하네스」가 들어가 있을 뿐 구조가 같다.**

세 번째가 **평가·관측**이고, 네 번째가 **온프레미스·클라우드를 넘나드는 LLM 서빙·라우팅**,
다섯 번째가 **STT·OCR 의 탐색·검증·도입 판단**이다. 아래 대조표가 이 다섯에 하나씩 붙는다.

**「한 영역의 깊은 강점」을 고르라면 — 하네스 런타임과 실행 기반이다.** 공고가 스스로 밝힌
우대 두 번째(*agent 의 실행 기반·런타임이나 안전 가드레일을 직접 설계·구현*)가 GLG 의 축과
같고, 그것이 **혼자 주장한 것이 아니라 제3자가 그 확장점을 찾아 들어와 증명된 축**이다.
