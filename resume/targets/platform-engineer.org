* Summary

I run infrastructure as declared state and defend it with written policy rather than tribal
memory. A self-hosted multi-agent harness on Oracle Cloud ARM survived repeated upstream releases
because a latency regression was instrumented back to a spinning gateway process, the rollback
target was chosen on evidence rather than recency, and the policy that followed — no two-version
jumps, stage on a non-production host for 24h+ before promotion, responsiveness as the SLO — is
dated in public commit history. The same discipline runs the GPU cluster and container services
behind it: declarative NixOS across every machine and source-to-binary provenance on every built
CLI.

My operating scope is self-hosted hosts and services, not multi-tenant Kubernetes or managed-cloud
platform operations.

* Core Competencies

- @@latex:\cvlabel{Declarative Infrastructure}@@ — NixOS across 4 machines, reproducible builds,
  and source revision / source-tree digest / binary SHA-256 provenance on every built CLI.
- @@latex:\cvlabel{Infra for AI Workloads}@@ — GPU cluster (3x RTX 5080), 17 containerized Docker
  services, PostgreSQL/pgvector, embedding and reranking served in-house rather than rented.
- @@latex:\cvlabel{Operational Policy}@@ — upstream tracking, staged promotion, regression
  instrumentation, rollback-on-evidence, and an SLO written down before an incident, not after.
- @@latex:\cvlabel{Data Pipelines}@@ — Airbyte connectors into PostgreSQL JSONB, Cloudflare Zero
  Trust perimeter, n8n workflow orchestration (40+ node workflows).
- @@latex:\cvlabel{Boundary-Respecting Dispatch}@@ — a published id-addressing substrate that lets
  systems reach each other without owning one another's auth or transcript — no OAuth proxying.
