# NHN 포트폴리오 v2 — 편집·이미지 계약

## 목적

`competency.org`가 “아직 이름이 굳지 않은 역할을 먼저 살아 온 하나의 흐름”을 선언한다면,
`portfolio.org`는 그 흐름을 **프로젝트별 문제·경계·판단·운영·인계로 증명**한다.

철학을 반복하지 않는다. 프로젝트 이름을 나열하지 않는다. 각 프로젝트에서 무엇이
달라졌고, 왜 그렇게 설계했으며, 누가 어떻게 이어받는지를 보여준다.

## 프로젝트 순서

1. **도메인 오너 에이전트** — 기존 업무 시스템에 읽기 전용 AX 접점
2. **OpenClaw 플랫폼 운영** — 변경·인시던트·롤백·승격 규칙
3. **andenken** — 런타임 밖으로 분리한 에이전트 기억·검색 계층
4. **entwurf + forge-config** — 하네스 디스패치와 검토 가능한 공유 작업면
5. **Embedded Linux·Backend·제품** — AX 계층 아래의 현실 시스템

## 프로젝트 공통 문법

각 프로젝트는 같은 순서로 쓴다.

1. **한 줄 명제** — 이 프로젝트가 증명하는 것
2. **맥락과 문제** — 왜 기존 방식으로는 부족했는가
3. **소유 범위와 협업면** — 내가 맡은 판단·구현·운영, 다른 조직과 맞닿은 경계
4. **시스템 경계** — 생성형 인포그래픽 한 장
5. **핵심 판단 2개 이내** — 기능 목록이 아니라 선택과 포기
6. **운영 후 상태 변화** — 허영 수치가 아니라 실제로 달라진 일
7. **인계·문서** — 다음 사람과 에이전트가 어디서 이어받는가
8. **확인 지점** — 공개 저장소·PR·노트 또는 `[사내]` 경계

`JD 관련성` 문단은 반복하지 않는다. 본문 자체가 JD를 증명하고, 대응표는 `:noexport:`
점검면으로만 둔다.

## 수치 원칙

- 규모를 크게 보이게 하는 숫자는 넣지 않는다.
- 판단을 재현하는 숫자만 남긴다.
- OpenClaw 장애의 CPU·부팅·메모리 수치는 증상→판단→복구를 설명하므로 후보로 남긴다.
- 사용자 수·문서 건수·노드 수·버전 횟수는 프로젝트의 판단을 설명하지 못하면 내린다.
- timeline 보강 전에는 날짜·횟수를 확정적인 성과처럼 키우지 않는다.

## 프로젝트별 단일 명제와 그림 계약

### 1. 도메인 오너 에이전트

- **명제:** 기존 IoT·상담·운영 시스템을 교체하지 않고 읽기 전용·증거 우선의 에이전트
  접점을 붙였다.
- **본문 중심:** `voscli`, `incidentcli`, 개인정보·자격증명 경계, 운영팀 피드백 루프.
- **보조 인프라:** 임베딩·리랭킹·GPU 서빙은 주인공이 아니라 기반 띠로만 둔다.
- **그림:** 업무 원천 → read-only seam → voscli/incidentcli → 담당자 에이전트 → 원천 근거.
  변경 경로 차단과 자격증명 비취급을 경계선으로 표시한다.

### 2. OpenClaw 플랫폼 운영

- **명제:** 에이전트 도구를 사용한 것이 아니라 상류 변경과 장애를 운영 규칙으로 번역했다.
- **본문 중심:** 증상 계측, 클린 부팅 재현, 마지막 정상판 롤백, 업스트림 수정 식별,
  승격 규칙.
- **그림:** 변경 → 회귀 → 재현 → 롤백 → 수정 식별 → 승격 규칙의 판단 시간축.
  수치는 판단에 필요한 작은 증거 태그로만 쓴다.

### 3. andenken

- **명제:** 기억을 특정 런타임에서 떼어 여러 하네스가 소비하는 독립 계층으로 만들었다.
- **본문 중심:** 세션·가든 두 라이브 트랙, 벡터+FTS, 점수 정규화, 한↔영 질의,
  회수 추적.
- **그림:** 세션/가든 → 임베딩·FTS → LanceDB → 점수 정규화 → 통합 검색 표면.
  active recall과 dream은 구현과 같은 무게로 그리지 않고 경계·로드맵으로만 표시한다.

### 4. entwurf + forge-config

- **명제:** 서로 다른 하네스가 세션 기억이 아니라 검토 가능한 durable state를 기준으로
  협력하게 했다.
- **본문 중심:** 정체성 기반 디스패치, 하네스 비종속, Forgejo 이슈·리뷰·인계,
  사람이 구현 우선순위를 소유하는 non-goal, 외부 Cortex 기여.
- **그림:** 왼쪽 `entwurf` 디스패치, 오른쪽 `forge-config` 이슈·검토·인계 루프.
  중앙 불변식은 “에이전트 기억이 현재 Forge 상태를 이기지 못한다”.

### 5. Embedded Linux·Backend·제품

- **명제:** 에이전트가 붙을 실제 시스템의 펌웨어·서버·앱·클라우드 경계를 알고 있다.
- **본문 중심:** 자원 제약 Linux 장치, Zig 펌웨어, Go 서버, Flutter 앱, 연결형/폐쇄망,
  실제 제품 출시.
- **그림:** 장치 → 서버 → 앱 → 클라우드/로컬 백엔드의 제품 세로축과 프로토콜 경계.
  Temporal·Saga 제안은 필요하면 상세 MD로 내린다.

## 이미지 생산 계약

- 프로젝트마다 **Gemini 생성형 인포그래픽 1장 필수**.
- Mermaid·Graphviz·결정적 다이어그램을 최종 폴백으로 사용하지 않는다.
- competency v3와 같은 흰 배경·navy/teal/amber·편집형 벡터 스타일을 쓴다.
- 기본 비율은 전부 16:9, 2K.
- 본문 사실과 경계를 먼저 확정한 뒤 프롬프트를 쓴다.
- 허용 라벨을 프롬프트에 명시하고, 설명 문구를 이미지가 임의로 출력하지 못하게 한다.
- 한글 오탈자·라벨 중복·구조 왜곡이 있으면 채택하지 않고 다시 생성한다.
- 그림은 장식이 아니라 프로젝트의 단일 판단을 보여준다.
- 캡션은 그림 제목을 반복하지 않고, 그림이 증명하는 판단을 한 문장으로 쓴다.
