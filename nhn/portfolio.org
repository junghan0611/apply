이 포트폴리오는 다섯 개의 프로젝트를 같은 문법으로 정리했습니다. *먼저 오는 것은 조직에서 수행한 AX입니다* — 기존 시스템에 AI 접점을 붙이고 운영·제품·개발 조직이 이어받게 만든 일. *그 뒤가 공개 검증 축입니다* — 회사 코드는 공개할 수 없으므로, 같은 능력을 공개 저장소·인시던트·제3자의 기여로 증명합니다.

각 프로젝트에서 사내 사실은 =[사내]= , 공개 검증은 =[공개]= 로 구분했습니다. *공개 증거가 없는 항목은 회사 코드라서 없는 것이고,* 그 옆에 같은 능력의 공개 저장소를 나란히 둡니다. 본문의 번호는 문서 끝 「참고자료」의 클릭 가능한 URL로 이어지며, *그 URL 목록 자체가 이 제출물의 검증 기능입니다.*

/기간 2025–2026 (진행 중) · 역할 설계·구현·운영 단독 · 대상 운영·QA·제품·개발 조직 · 스택 Clojure, Python, GPU·컨테이너, PostgreSQL·pgvector, Kafka, n8n, AWS·Oracle Cloud/

*맥락과 문제.* 스마트홈 IoT 플랫폼(헤이홈, 약 140만 사용자)은 이미 대규모로 돌아가는 운영 시스템입니다. 여기서 AX 전환은 시스템을 갈아엎는 일이 아니라, *도메인의 주인이 자기 데이터를 자기 언어로 안전하게 물을 수 있는 접점을 붙이고, 그 답을 원자료까지 역추적할 수 있게 만드는 일이라고* 봤습니다.

*내 역할.* 사내 AI 인프라와 업무 데이터 접점을 설계·구현·운영하는 단독 담당입니다.

*아키텍처.* 두 층으로 나눴습니다.

- *AI 인프라(서빙 계층).* 문서 임베딩과 리랭킹을 외부 API에 의존하지 않고 *GPU·컨테이너 위에서 직접 서빙합니다*. 사내 지식(문서 임베딩 2,945건)을 벡터 검색면으로 다루고 [사내], 벡터 저장은 PostgreSQL·pgvector [cite:@pgvector], 원천 수집은 n8n 40+ 노드와 데이터 파이프라인으로 자동화합니다. *파인튜닝 중심이 아니라 임베딩·리랭킹·검색 품질·프롬프트 설계라는 실서비스 최적화 축이고*, 이 감각은 공개 저장소 andenken에서 그대로 검증됩니다 [cite:@repo-andenken].
- *읽기 전용 에이전트 워크벤치.* 기존 IoT·상담 시스템을 교체하지 않고 접점만 붙였습니다.
  - =incidentcli= (Clojure) [사내] — 운영 장애와 VOC→디바이스 추적을 *하나의 KST 단일 시간축으로 회수·정렬합니다*. Slack 알림·API 모니터 DB·Kafka·클라우드 트레일·IoT 디바이스 로그·런타임 미러를 9개 수집기로 묶되, *모든 외부 호출은 읽기 전용이고 덤프를 쌓지 않습니다.* 수집 결과는 SPEC envelope로 검증하고 인시던트 기록은 append-only이며, =phone/email → uid → device → session/event/status= 를 잇습니다.
  - =voscli= (Clojure) [사내] — 운영팀이 매일 보는 상담 데이터 위에서 *숫자의 단위·기간·포함정책을 고정하고, 모든 근거를 개별 상담 id까지 역추적하게* 만들고, 평소와 다른 신호를 자동 검출해 운영팀이 읽는 Markdown 표면으로 고정합니다.

*핵심 판단 — 권한과 경계를 먼저 그었습니다.* 이 접점들은 실제 고객 개인정보와 자격증명을 다룹니다. 그래서 설계에 경계를 문장으로 박았습니다 — *자격증명은 에이전트가 취급하지 않고,* 변경·실행(mutation) 경로는 차단하며, 원시 개인정보는 표준입력 seam으로만 흐르고 문서·커밋에 남기지 않습니다. *"자연어를 실데이터로 잇되 읽기 전용 경계를 절대 넘지 않는다"* 가 이 프로젝트의 규율입니다.

*운영·성과.* voscli는 "고도화보다 운영자가 쓰고 싶게 만드는 것이 먼저"라는 원칙으로 *운영팀 일상 사용에 진입했고*, 1년치 상담 원자료를 운영자·봇 워크스페이스가 =git pull= 한 번으로 쓰도록 backfill했습니다 [운영 기록]. 별도 대시보드 제품을 만드는 대신, 운영팀이 이미 읽는 표면(Markdown·메신저)에 결과를 실었습니다.

*인계·협업.* 운영팀의 상담 고통을 듣고 → 개발 가능한 요구로 번역하고 → 제품·개발과 경계를 합의하고 → 워크벤치를 제공하고 → 피드백을 다시 데이터·이슈로 되돌리는 루프를 돌렸습니다.

*JD 관련성.* 주요 업무 ①(AX 인프라 구축·관리·운영)과 자격 요건(개발·비개발 AX)에 직접 대응합니다.

*핵심 증거.* [사내·비공개] incidentcli·voscli 운영 · [공개] 같은 능력의 임베딩·검색 구현 andenken [cite:@repo-andenken] · pgvector [cite:@pgvector].

- =entwurf= — 하네스들이 상대의 인증·대화록·런타임을 소유하지 않고 *정체성만으로 서로를 호출하게 하는 얇은 기층* [cite:@acp-spec;@repo-entwurf]. Claude Code와 Codex를 매일 이 위에서 위임합니다 [cite:@claude-code;@openai-codex].
- =forge-config= — 도메인 오너와의 대화에서 발견된 요구를 셀프호스팅 Forgejo 이슈로 굳히고 [cite:@forgejo;@repo-forge-config], 봇이 해당 도메인 에이전트에게 *읽기 전용 1차 리뷰로* 넘기고, 결과를 durable store에 남기는 루프입니다.

*핵심 판단 — 값어치는 "하지 않기로 한 것"에 있습니다.* 문서에 박아둔 non-goal이 셋입니다 — *자동 코딩 공장이 아니고,* 운영 대시보드 제품이 아니고, 무엇을 구현할지 사람이 정하는 일을 대체하지 않습니다. =forgebot= 은 *디스패처이자 기록자이지 구현자가 아닙니다.* 목적은 하나 — *세션 메모리와 웹훅 재생이 현재 Forge 상태를 절대 이기지 못하게*, 즉 에이전트의 기억보다 durable store가 권위를 갖게. 이것이 BMAD류 워크플로와 같은 문제층의 독립 구현입니다 [cite:@bmad-method].

*운영·성과.* auto-fix 레인이 두 리포에서 GREEN이고, *재생·멱등성 스모크에서 리포트 중복 생성이 없었습니다* [운영 기록].

*인계·수용.* 자기 저장소로 증명되지 않는 것 하나 — *수용(reception).* 제가 그은 확장 경계에 *외부 개발자가 Snowflake Cortex Code 백엔드 기여를 실제로 열었고* [cite:@pr-entwurf-40], 제 코드가 상류 프로젝트에 받아들여진 기록도 함께 둡니다 [cite:@pr-ghostel-343;@pr-ghostel-510]. *이 줄이 가장 위조하기 어렵고, 회의적인 독자가 가장 먼저 확인하는 줄입니다.*

*JD 관련성.* 자격 요건(Agentic AI 활용 개발)과 우대 사항(BMAD·AI Workflow)에 대응합니다.

*핵심 증거.* [공개] entwurf [cite:@repo-entwurf] · forge-config [cite:@repo-forge-config] · 외부 기여 PR \#40 [cite:@pr-entwurf-40] · 상류 수용 [cite:@pr-ghostel-343;@pr-ghostel-510].
